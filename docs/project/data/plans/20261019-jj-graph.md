# Implement jj graph normalization

## Context

The author's guide "Architectural Graph Engineering in Jujutsu" describes
skeleton planning, four refactoring patterns, and a four-pass crawler that
normalizes a change graph against the code's dependency graph. The author asked
for all of it, implemented as rigorously as possible, with Quint and
property-based tests from the start. [jj-graph](../features/jj-graph.md) is the
feature.

## Approach

Specify first: `spec/Normalize.qnt` (normal form, hoisting, plan),
`spec/Apply.qnt` (one-operation apply), `spec/Skeleton.qnt` (ghost graph). The
specification found that the guide's crawler is unsound and incomplete, so the
Rust core computes the normal form directly
([decision](../architecture/jj-graph-normal-form.md)). Hegel properties,
quint-connect conformance, and end-to-end properties in real repositories check
the implementation. Rejected: implementing in Nushell inside `ci`, which has no
tree-sitter and weaker typing for the core.
